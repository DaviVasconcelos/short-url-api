# Deploy

Production runs on **Render Free** (Docker web service) with **Neon Free** (PostgreSQL). Both are free, no credit card. The Render service is declared in [`render.yaml`](../render.yaml), so the deploy is reproducible instead of a set of dashboard clicks.

| Piece | Value |
|---|---|
| Public URL | `https://shorturl-davi.onrender.com` |
| Render service | `shorturl-davi`, `runtime: docker`, `plan: free`, region `virginia` |
| Health check | `/health/live` (liveness only) |
| Database | Neon Free, region AWS `us-east-1`, **direct** connection |
| Migrations | Applied on startup by `DatabaseMigrationRunner` |
| CI gate | `autoDeployTrigger: checksPass` |

> **Last verified:** 2026-10-28 — the deploy answered `200` on `/health/live`, `/health` and Swagger, created an anonymous link as `https://shorturl-davi.onrender.com/<code>`, redirected `302`, tracked the click, and returned `401`/`403`/`404` for the delete paths. `GET /` redirects to Swagger so the bare demo URL is usable.

## Why a direct Neon connection

Neon's pooled endpoint (`-pooler` hostname) is PgBouncer in **transaction mode**. Neon's own docs recommend a direct connection for schema migrations, `pg_dump`, and anything that depends on session state. Because this app applies migrations during startup, `ConnectionStrings__Postgres` must use the **direct** host — the one **without** `-pooler`.

## 1. Neon

1. Create a project in <https://console.neon.tech> → region **AWS us-east-1** (closest to `virginia`).
2. Copy the connection string for the default database (`neondb`) and the owner role.
3. Convert it to the ADO.NET form used by Npgsql:

```text
Host=ep-xxx-xxxx.us-east-1.aws.neon.tech;Database=neondb;Username=neondb_owner;Password=...;SSL Mode=Require;Trust Server Certificate=true;Maximum Pool Size=20;Timeout=30
```

Keep `Maximum Pool Size` small: Neon Free caps concurrent connections, and one web instance does not need more than 20.

Do **not** create tables by hand. The first Render deploy runs `InitialPostgres` and `AddUsersAndOwnership` automatically.

## 2. Render

1. <https://dashboard.render.com> → **New** → **Blueprint**.
2. Select `DaviVasconcelos/short-url-api`. Render reads `render.yaml` and shows the `shorturl-davi` service.
3. When prompted for `ConnectionStrings__Postgres` (declared `sync: false`), paste the string from step 1.
4. Apply. The first build publishes the Docker image and `healthCheckPath: /health/live` gates the rollout.

`Jwt__Key` is generated by Render (`generateValue: true`) once and preserved across deploys, so tokens are not invalidated on every release.

### Environment variables

| Variable | Source | Notes |
|---|---|---|
| `Database__Provider` | `render.yaml` | `Postgres` |
| `ConnectionStrings__Postgres` | dashboard secret | Direct (non-pooler) Neon host |
| `Jwt__Key` | generated by Render | At least 32 bytes |
| `Swagger__Enabled` | `render.yaml` | `true` for the public demo |
| `ShortUrl__BaseUrl` | unset on purpose | Links derive from the request host |
| `PORT` | Render | Injected automatically; the image listens on it |
| `Database__MigrateAttempts` | optional | Default `5` |
| `Database__MigrateDelaySeconds` | optional | Default `2` |

## 3. Smoke test

Run against the public host after the first deploy. `check` values are status codes unless noted.

| Check | Expected |
|---|---|
| `GET /health/live` | `200` |
| `GET /health` | `200` (proves Neon is reachable) |
| `GET /` | `302` to `/swagger` |
| `GET /swagger/index.html` | `200` |
| `POST /api/urls` (anonymous) | `201`, `shortUrl` starts with `https://` |
| `GET /{code}` | `302` + correct `Location` |
| `GET /api/urls/{code}` | `clickCount` incremented |
| `POST /api/auth/register` | `201` + token |
| `POST /api/auth/login` | `200` + token |
| `GET /api/auth/me` | `200` + registered email |
| `POST /api/urls` (Bearer) | `201` |
| `GET /api/urls?page=1&pageSize=20` | `200`, owned link listed |
| `DELETE /api/urls/{code}` (owner) | `204` |
| `DELETE` without token / other user / unknown code | `401` / `403` / `404` |
| `POST /api/urls` with alias `swagger` | `400` |
| 31st `POST /api/urls` in a minute | `429` + `Retry-After` |
| `GET /{code}` after a redeploy | `302` (data lives in Neon) |

The `https://` check matters: if links come back as `http://`, `ForwardedHeaders` is not being applied and the bug is in the app, not in the Render configuration.

Two rows are better run locally: the 31st-request `429` creates 30 throwaway links, and `410` cannot be produced through the API at all (`expiresInDays <= 0` means "never expires", which is covered by service tests). Use the local rehearsal below for both.

```bash
HOST=https://shorturl-davi.onrender.com

curl -fsS -o /dev/null -w 'live %{http_code}\n'   "$HOST/health/live"
curl -fsS -o /dev/null -w 'ready %{http_code}\n'  "$HOST/health"
curl -fsS -o /dev/null -w 'swagger %{http_code}\n' "$HOST/swagger/index.html"

created=$(curl -fsS -X POST "$HOST/api/urls" \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/smoke","expiresInDays":30}')
echo "$created"

curl -sS -o /dev/null -w 'redirect %{http_code} -> %{redirect_url}\n' "$HOST/<shortCode>"
curl -fsS "$HOST/api/urls/<shortCode>"
```

## 4. Operations

- **Cold start:** Render free instances spin down after ~15 minutes idle and Neon suspends compute. The first request can take up to a minute. This is expected; do **not** add a keep-alive ping — 750 free instance-hours per month do not survive one.
- **Logs:** Render → service → Logs. Migration failures are logged with the attempt number and the exception, so an unreachable Neon or a bad SSL setting is visible without guesswork.
- **Redeploy:** push to `main`; Render builds only when CI passes. A manual deploy from the dashboard skips the CI gate.
- **Rollback:** Render → Deploys → previous deploy → **Rollback**. The database is untouched.
- **Database:** Neon keeps the data; a suspended compute wakes on the next connection. Use Neon branches for experiments instead of touching `neondb`.
- **Rotating `Jwt__Key`** invalidates every issued token (users must log in again).

## Local rehearsal

Reproduce production locally with real PostgreSQL before touching the deploy:

```bash
docker run --rm -d --name shorturl-pg \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=shorturl \
  -p 5432:5432 postgres:16-alpine

docker build -t shorturl .

docker run --rm -d --name shorturl-pgapp -p 10000:10000 \
  --add-host=host.docker.internal:host-gateway \
  -e PORT=10000 \
  -e Database__Provider=Postgres \
  -e 'ConnectionStrings__Postgres=Host=host.docker.internal;Port=5432;Database=shorturl;Username=postgres;Password=postgres;SSL Mode=Disable' \
  -e Jwt__Key=dev-only-key-at-least-32-bytes-long \
  -e Swagger__Enabled=true shorturl
```

Then restart the app container and confirm an existing short code still redirects. `docker rm -f shorturl-pgapp shorturl-pg` cleans up.

To see the retry path, point the connection string at a closed port and set `Database__MigrateAttempts=2` / `Database__MigrateDelaySeconds=1`: the log shows one retry warning followed by a fatal error, and the container exits non-zero.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Deploy fails at startup, log says migration failed | Neon host unreachable, wrong password, or SSL | Use the direct host, check `SSL Mode=Require`, confirm the project is not deleted |
| `sslmode` / certificate error | `SSL Mode=Disable` in production | Set `SSL Mode=Require` |
| Migration hangs then times out | `-pooler` host used for migrations | Switch to the direct host |
| Links use `http://` | `ForwardedHeaders` not applied | Fix the app; do not pin `ShortUrl__BaseUrl` |
| Deploy waits forever | `checksPass` and CI is red or not reporting | Fix CI, or set `autoDeployTrigger: commit` temporarily |
| `429` on the first request | Shared corporate NAT hitting the 30/min per-IP limit | Expected; the limit is per client IP |
