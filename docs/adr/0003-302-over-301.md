# ADR-0003 — `302` instead of `301` on redirects

- **Status:** Accepted
- **Phase:** 1a (domain + database)

## Context

`301 Moved Permanently` is cacheable by browsers and intermediaries "forever". For a shortener that counts clicks and can expire links, that cache is hostile: a browser that saw a `301` may stop calling the API entirely, so the click is never counted and the expiry is never enforced. A link whose target must be changed later would also keep redirecting to the old target.

## Decision

`GET /{shortCode}` always answers `302 Found` with a `Location` header, and missing or expired codes answer `404` and `410` respectively.

## Consequences

- Positive: every click reaches the API, so `clickCount` stays truthful and expiry is evaluated per request.
- Positive: targets and ownership rules can change without fighting browser caches.
- Negative: no client-side caching benefit — every redirect costs a request, which is exactly why the cache-aside on the database read exists (see ADR-0006).
- Negative: `302` is technically "temporary", which slightly understates intent for permanent links. Accepted: correctness of stats wins over HTTP semantics purity.
